# Web 页面

在浏览器里输入当前已知异常，阅读结构化历史参考、展开核对来源，并下载本次运行记录。
页面与回答 API **同源**，复用已验收的链路：PostgreSQL 快照 → R3 检索 → 证据上下文 → 生成 → 引用守卫。

范围：搜索历史案例、案例资料库、设置三个中文入口，必要的静态资源托管与使用说明。不含前端构建链、认证、公开部署、流式响应或后台任务。
页面是**历史参考**入口，不判断当前 Incident 的最终 Root Cause；引用可定位不等于引用支持原句。

## 页面位置

| 项目 | 位置 |
|---|---|
| 页面 | `GET /`（例如 `http://127.0.0.1:8000/`） |
| 案例资料库 | `GET /library`，概览、筛选分页、完整详情、编辑、新增、删除、主数据、模板、上传与恢复 |
| 设置 | `GET /settings`，提供模型状态、输出上限、高级 Top K |
| 静态资源 | `/static/app.css`、`/static/app.js`，源码在 `src/casetrace/web/` |
| 资源定位 | 按模块位置（`casetrace.api.WEB_DIR`）解析，与启动目录无关 |

`GET /`、`/library`、`/settings` 与 `/static/*` 只读取文件，不连接数据库、不构造模型；`/health`、`/answer`、`/docs`、`/openapi.json` 行为不变。

## 打开页面

**宿主 `uv` 路线**（数据库需已执行 `storage prepare`，见 [PostgreSQL 环境说明](postgresql.md)）：

```bash
uv run --locked uvicorn casetrace.api:app --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000/
```

**容器路线**（见 [Docker 运行链路](docker.md)）：

```bash
docker compose up -d --wait api        # 数据库已 init / import
curl --fail-with-body http://127.0.0.1:8000/health
# 端口以 CASETRACE_API_PORT 为准；浏览器打开 http://127.0.0.1:<端口>/
```

“搜索历史案例”调用 `/search`，无需模型密钥。“生成调查参考”单独调用 `/answer`（需 `DEEPSEEK_API_KEY`，**会计费**）。页面通过 `/model-status` 显示配置状态；未配置或无法读取状态时生成按钮禁用，搜索仍可用。配置状态不证明模型服务可用，调用失败仍按失败展示。

## 案例资料库浏览

进入「案例资料库」可直接浏览整库，无需调查 Query 或模型密钥。概览显示名称、来源类型、案例/明细/证据数、更新时间、完整可用日期与依据、审阅状态；技术身份与摘要默认折叠。来源类型表示载入途径，CSV 上传并不保证资料真实。

列表支持关键词（编号、异常描述、历史根因、生产批或客户批）、产品、客户、已确认异常站点及发现阶段筛选，按案例分页。点击「筛选案例」应用条件，「清空筛选」返回第一页。产品、客户、阶段须在同一条明细上同时满足；列表中的日期范围、产品与子记录数始终描述整案。整库案数、匹配案数与本页案数分别显示。

点击编号查看完整结论、逐条批次明细、Case 级调查证据、分组及关联理由、来源沿革；返回保留已应用筛选与页码。来源结案声明 confirmed/NDF 与待人工审阅状态分别展示。内置合成候选只说明生成沿革；CSV 显示各记录的报告位置及原文件行号。下方可展开只读主数据，查看客户/产品族/路线及名称与编号；发现阶段和路线允许工序不能代替已确认异常工序。

资料更换后，旧筛选、详情或主数据请求会返回冲突；页面清除旧内容并提示「资料已变化，请刷新核对」，不拼接新旧快照。服务错误、空库和筛选无结果分别展示。零案时仍可新增案例、导入 CSV 或恢复九案演示库；新增、编辑、删除与折叠修订记录均已提供，保存成功后立即供新搜索使用。

浏览器专项回归（真实 Chromium + HTTP 夹具，无数据库、无模型）：

```bash
CASETRACE_SCREENSHOT_DIR=docs/plans/dataset-management/evidence/02 node scripts/web_case_browser_check.mjs
node scripts/web_case_editing_check.mjs
node scripts/web_case_creation_check.mjs
node scripts/web_case_deletion_check.mjs
node scripts/web_dataset_browser_check.mjs
```

截图与验证记录见[资料库工作包 02](../plans/dataset-management/issues/02-case-browser.md)、[03](../plans/dataset-management/issues/03-case-editing.md)、[04](../plans/dataset-management/issues/04-case-creation.md)、[05](../plans/dataset-management/issues/05-case-deletion.md)。夹具检查不代替真实 PostgreSQL 验收；真实库测试需配置 `CASETRACE_TEST_DATABASE_URL`。

## 更新当前资料（CSV 上传）

进入「案例资料库」，下载唯一模板或上传格式示例（1 案、2 明细、3 证据），按[上传格式](../data/upload-format.md)填写。每个 Case 支持多个 Detail 和多个 Case 级调查项目；每条来源必须具体填写。Case 行的来源结案声明 `closure_status` 为 `confirmed` 或 `NDF`，资料审阅状态仍固定为 draft。

填写数据集名称、整份资料完整可用日期与依据，确认可用性声明后点击「校验并整体替换当前数据集」。成功后页面显示名称、数量和更新时间；搜索页自动读取当前数据的登记日期。错误会显示可定位的 CSV 行列，不做部分导入。网络异常导致结果不明时先核对当前状态，页面不会自动重传。

内置示例和旧评估指标不与上传资料混用。重启服务保留已上传数据；已开始的回答使用原快照完成。详细 API 与事务边界见 [HTTP 接口](api.md)。

## 编辑已有案例与查看修订

搜索首页可点击「管理与编辑案例」进入资料库，再点击列表中每案的「编辑整案」直接修改；也可先打开案例详情再编辑。历史结论、批次明细、Case 级调查证据分区填写；可以增删明细/证据，统一点击编辑页顶部的「保存整案」或「取消编辑」；操作栏随长表单滚动保持可见。既有编号不变，新增子记录保存后由系统分配编号。产品展示名称与编号，并联动显示客户、产品族和路线；异常工序需要根据调查明确选择。

普通修改自动沿用原出处，不反复填写来源。需要换出处时展开该记录的来源区域并明确勾选；新增子记录须登记报告编号/名称/具体位置，或人工合成说明及位置，不伪造 CSV 行号。修改后的案例会标记网页人工修订，原 CSV 行号、报告或合成候选仅表示来源沿革。

资料完整可用日期和依据默认沿用。需要调整时勾选「本次同时调整整份资料日期或依据」，并确认整份资料在新日期前已结案且完整可用；保存会检查其他案例的日期，不能只声明正在编辑的一案。

字段校验失败会保留输入并显示可点击的错误定位。未保存离开时提示放弃；过期页面保存返回冲突、保留草稿并停用旧身份保存，不自动合并。网络结果不明时也保留输入，先刷新核对当前资料是否已经保存，再重新编辑；不会自动重传。编辑期间暂停同页上传/恢复，保存中禁止重复提交。

详情下方的「网页修订记录」默认折叠，可展开查看时间、中文变更字段和增删子记录编号。没有历史就显示暂无网页修订；原样保存和取消不造记录。保存成功后新搜索使用新资料，进行中的回答及其下载仍保留旧快照。刷新和正常重启保留数据库内容；CSV 或恢复整体替换时同步清除旧修订。

真实数据库验收状态见 [03 工作包](../plans/dataset-management/issues/03-case-editing.md)，浏览器 HTTP 夹具通过不代表已验证运行实例持久性。

## 新增完整案例

资料库「浏览案例」上方提供「新增案例」，无需先打开旧案例。新增与编辑共用中文分区表单：默认一条明细与一项证据，可继续添加；Case、明细与调查证据编号全部由服务端生成，保存后显示在详情中。批号按文本保存，前导零不丢失；新案默认不入组，需要分组时仍按现有规则另行处理。

每条新记录必须登记首次来源：报告需填写编号、完整名称和本条记录的具体位置；人工合成需填写合成说明和位置。同一报告可复用编号与名称，但位置必须逐条对应，页面不提供 CSV 文件/行号字段。产品只可选当前合法主数据，选择后显示客户、产品族与路线；异常工序须根据调查明确选择。

保存前可以暂时不完整，点击「保存整案」时统一校验；校验失败保留输入并定位到具体记录与字段。成功返回后展示新案详情，列表计数与新搜索立即使用新资料；保存不需要模型密钥。过期页面或重复提交返回冲突，不自动重试；网络结果不明时先核对列表是否已出现新案。

## 删除案例与空库

详情页提供「删除案例」。确认面板展示案例编号、异常摘要、明细/证据数量、所属分组及删除后剩余成员数，并明确说明不提供回收站、不能撤销；取消不改变任何数据，删除失败也不产生修订记录。

服务端会重新核对当前资料身份并对删除后的完整候选集执行现有规则：三成员组删一案后仍有两案可以成功；两成员组删一案会被 CR-38 拦住，不自动解散组或改写其他案例。合法删除会移除该案、明细、证据、入组关系、来源映射及该案的网页修订记录，其他案例、主数据与设置保持不变。删除成功后新列表、计数与新搜索不再包含该案；已经开始的旧回答与下载仍属原快照。

删除最后一个合法的无分组案例后，资料库进入空库状态：界面区分「总数为零」与「筛选无结果」，并提供新增案例、导入 CSV、恢复完整演示数据入口。空库时直接请求搜索或生成返回明确的空库业务状态，不构建空检索、不调用模型；CSV 导入仍要求至少一案。刷新与正常重启保留零案状态，不会自动回填九案。

## 修改模型与检索设置

设置页只支持现有 DeepSeek 路线。回答输出上限为 2048 或 4096 tokens（默认 4096），高级 Top K 为 1–10 的整数（初始为 4）。保存后下一次网页/API 请求生效，当前回答保持原参数；刷新、重启和上传替换均保留设置。CLI 实验参数独立。搜索页显示已保存值，本次实际 Top K、生成时的输出上限与温度可在结果的“检索配置与资料身份”中核对。

读取失败时设置控件禁用，不以默认值替代；保存结果不明时点击“重新读取已保存设置”核对。较小输出上限可能截断 JSON，仍明确报告失败，不自动重试。密钥由本机 `.env` 管理，网页只显示已配置/未配置。修改密钥后，宿主 Python 重启进程；Docker 重新创建 API 容器（`docker compose up -d --force-recreate api`），普通 restart 不更新注入的环境变量。

## 离线验收（不调用模型、不计费）

只在真实测试库上运行的固定回放入口：临时 schema 导入 dev-v3，把保存的 Q005 v10 回答用离线替身返回。
它复用既有存储与回答代码，不新增生产模拟开关。

```bash
uv run --locked python scripts/web_demo_smoke.py --port 8010 --search-only
# 浏览器打开 http://127.0.0.1:8010/，提交脚本打印的那条 Development Query 原文
```

- 需要 `CASETRACE_TEST_DATABASE_URL`（真实测试库）；缺省时脚本直接退出；
- 临时 schema 名为 `casetrace_web_smoke_<随机>`，Ctrl+C 或 `kill -TERM <pid>` 退出时自动删除；若删除失败会打印手工清理命令；
- `--search-only` 强制模型密钥为空，可检验真实无密钥搜索；去掉该参数时只回放打印的 Q005 v10 回答；
- 真实模型调用数为 **0**；本入口只用于验收，不提供任意响应注入。

下载可见性与缺损记录的浏览器回归（离线服务启动后，在另一个终端运行）：

```bash
CASETRACE_CHROME_BINARY=/usr/bin/chromium node scripts/web_demo_browser_check.mjs http://127.0.0.1:8010/
```

需要 Node 22+ 和 Chrome，默认使用 macOS 的 Chrome 路径；上例指定 Linux Chromium，其它安装位置可设置 `CASETRACE_CHROME_BINARY`。脚本每次创建独立浏览器 profile，对 ABC 示例和空命中发出真实 `/search` 请求；生成、支持不足和失败用固定响应验证，阻止向服务端发送 `/answer`。不调用真实模型，退出后删除该 profile。另验证设置保存、刷新、非法值、失败提示、下一次搜索生效与窄屏布局。可追加截图目录参数保存截图。脚本会修改验收实例的设置并在结束时恢复 4/4096，请仅用于独立验收实例。

## 页面行为

**输入。** Query 文本域、当前快照日期与提交按钮。网页提交 `query`、`known_at`，省略 `top_k`，由服务端使用请求开始时的最新设置。空白 Query、缺失日期在本地拒绝，不发请求。
异常输入框和搜索／生成按钮是主要入口。“试用示例”位于按钮下方，默认折叠，展开后提供 A 焊线剥离（Q001）、B 塑封空洞（Q002）、C BGA 缺球（Q003）。“填入示例”使用已确认的 Development Query 原文，清除上次结果但不提交，随后收起示例并聚焦输入框；问题仍可编辑。首次加载读取模型状态、数据状态和已保存设置，不自动检索或生成。日期在搜索页高级选项中，Top K 在设置页高级区域。

**状态。** 提交后锁定输入并禁止重复提交，完成后恢复；新请求开始即清除旧回答与旧下载目标。
结果按 HTTP 状态与响应 `status` **共同**判定：

| 返回 | 页面行为 |
|---|---|
| 检索 200 + `retrieved` | 展示原始问题、候选排名和可展开的历史 Case／Detail／Evidence 等原文，明确没有调用模型或判断支持程度；可下载检索记录 |
| 检索 200 + `no_hits` | 明确没有检索候选、未调用模型；不声称资料库不存在相关案例 |
| 生成 200 + `ok` | 展示运行摘要、采用案例、候选排名与原文、未采用候选及具体缺口；`case_answers` 为空时显示“支持不足／本次未采用历史案例”，使用警示状态，仍表示流程正常完成 |
| 200 + `no_hits` | 显示无候选与具体不足，不生成空的成功案例卡片 |
| 200 + `empty_dataset` | 显示“当前资料库为空”，未构建检索、未调用模型；提供前往案例资料库新增/导入/恢复的入口，不生成下载记录 |
| 422 | 显示字段校验提示，保留输入供修改 |
| 502 / 503（模型失败、格式失败、引用失败） | 按 `status` 与安全 `message` 显示失败；失败记录可下载但按钮标注“下载失败记录”；记录里的 `answer_text` 不作为成功回答展示 |
| 503 `service_unavailable` / 500 | 显示安全说明，`record=null` 可处理，不提供下载 |
| 网络/解析失败、结构无法识别 | 明确本次未得到可用响应，保留输入供手动重试；不自动重试 |

**结构化回答。** 成功生成后先显示“采用的历史案例”概览表，列出历史案例编号、产品与客户／生产批／客户批、发现阶段与日期、历史异常原文。基本信息来自该 Case 的历史上下文，不从当前 Query 或其它 Case 补造；一案多条 Detail 时保持各条产品、批次和发现信息的对应关系。点击表格的案例编号可展开并定位对应详情，也可通过下方的原生折叠入口自行展开／收起。

逐案详情分为相关依据、当前／历史事实对照、历史原因／检查／措施及来源；桌面事实对照分栏，窄屏改为单栏。表格在窄屏中独立横向滚动。当前信息缺口保持可见；未采用候选、排名、所有候选原文和请求元数据收在默认折叠的“核对检索候选与本次请求”中，避免默认铺开重复内容。只改变展示，不改变模型输出、采用结果或记录下载内容。

**来源与下载。** 每个采用案例详情中的“来源与原始上下文”默认折叠：展开可看到 `sources` 的 `case_id · field`，以及本次上下文里该 Case 的原始 Case／Detail／Evidence／来源记录／产品背景／异常工序。
下载按钮给出本次 `record` 的 JSON（内容与 API 返回值一致）；替换或清除时会释放对象 URL。

**文本安全与隐私。** 页面所有动态文本都经文本节点写入，Query、模型输出、来源与错误文本不会被当作 HTML 执行；
页面不收集或展示 API key、数据库连接或 schema，模型仅显示配置布尔状态；不使用本地存储或 cookie 保存历史。

## 边界与已知限制

- 回答是历史参考，不产生新的 Ground Truth，也不升级 draft Case；
- 只绑定本机地址，无认证、无连接池、无流式响应、无后台任务；
- 页面不提供数据源/schema/模型选择，跑哪份数据由服务端配置决定；
- 浏览器默认请求 `/favicon.ico` 会得到 404（页面未引用它，不影响功能）；
- `HEAD /` 返回 405：页面按 `GET` 提供（浏览器与 `curl` 的 GET 均正常），`/static/*` 支持 HEAD；用 HEAD 做存活探测请改探测 `/health`；
- 页面的前端行为由 `tests/api/test_web.py` 覆盖静态契约，实际交互以浏览器核验为准；模拟响应只证明前端行为，不代替真实数据库集成证据。

### 恢复完整演示数据

案例资料库页“载入完整演示数据”在明确确认后，将当前案例资料及网页修订记录整体替换为项目 V1 的九案完整合成库（9 明细、9 证据、1 组、3 入组关系），保留基线来源、五条 Query 和 2026-09-15 完整可用日期。上传格式示例只有一案，用于说明 CSV 格式。

恢复使用当前主数据校验，失败保留原资料；不替换主数据或重置模型/检索设置。每次恢复产生独立运行身份，过期恢复返回冲突，需刷新核对后再次确认。网络结果不明时先刷新核对，不自动重传。已开始的回答及其下载仍保留旧快照，新请求读取恢复后的资料。正常重启保留当前快照，包括已登记的零案快照。

恢复不代表资料已人工审阅或回答质量经过重新评估。CSV 导入、恢复、整案编辑、新增与删除统一检查预期快照身份；替换成功会清除旧修订记录。


## 更新后仍显示旧页面

应用更新不会自动删除浏览器已经保存的旧 HTML。旧版没有明确缓存策略时，可能出现“带参数地址是新版，点击查询/设置又回旧版”。已修复的服务要求 HTML/静态资源每次重新校验，并给导航与资源附加同一 UI 内容版本。

如果浏览器曾加载旧版，先打开一次 `http://127.0.0.1:8000/?refresh_ui=1`（自定义端口相应替换）。该入口通过 `Clear-Site-Data: "cache"` 请求清除此站点 HTTP 缓存，不清 cookies、storage、案例或实例设置。然后正常使用首页、设置和案例资料库；不需要反复添加诊断参数。已经打开的旧标签页仍须重新载入。

缓存控制依据：[HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、[Clear-Site-Data](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Clear-Site-Data)。Chromium 的缓存升级专项已实际验证本机 HTTP 回环地址；其他浏览器尚未实测，不声称全部平台完成验收。
