## 推荐结构与交互

维持三个顶级入口：案例检索、案例资料库、设置。资料库内增加“浏览案例 / 数据管理”子导航，使用现有路由的查询参数实现即可。

1. 案例检索：简短用途说明 + 异常输入 + 可直接填入的示例 + 主按钮。就近显示数据就绪状态；搜索后结果数与结果列表优先。生成调查参考保留为次级明确动作，标明调用模型和费用可能性。
2. 结果行：编号、异常摘要、已有产品/站点、历史结案原因摘要、证据数量。缺失字段写“未提供”，不编造匹配理由。详情打开保持列表上下文；技术分数、请求配置、JSON 下载放到次级“运行详情”。
3. 案例详情：标题/编号、来源类型、结案声明与审阅状态；“历史结论 / 调查证据 / 批次明细 / 来源与修订”锚点导航。证据卡显示调查类型、结果、相关标记、现有报告位置。无附件接口就展示来源文字定位，不承诺 PDF 预览。
4. 调查参考：当前事实、历史事实、采用依据、信息缺口分区；引用定位到本次快照证据，不能静默跳到更新后的资料。历史根因始终明确标识。
5. 资料库：搜索框与常用筛选并排，应用后的条件可见，显示全库/匹配/本页数量；新增次级、编辑进入详情；恢复和整库替换只在数据管理。
6. 先通过一致列布局支持比较。可选后续加入当前候选的 2–3 案对比，只比较现有字段；不默认新增收藏、工作台或后台任务。

参考企业工具的列表—详情、渐进展开、就近校验和明确空状态模式，而非照搬其 Dashboard。Tabler 官方提供导航、表格、分页、空状态与表单组件，可作为具体实现参考：https://docs.tabler.io/ 。此次并未声称实测 Jira/ServiceNow 等产品。

## 组件方案

推荐 Tabler，保留原生 JS。先使用样式、表单、按钮、导航、表格、badge、alert、pagination；仅在确有需要时接入交互 JS。固定版本并将必要资源放入静态目录，避免演示依赖运行时 CDN。先检查全局 CSS 重置与现有 .card/.badge/.button 类冲突，逐页替换，防止两套样式叠加。

shadcn/ui 官方安装路径面向 React 等框架生态（https://ui.shadcn.com/docs/installation），本仓库没有对应构建链。采用它需要额外框架/工具链和组件重写，不符合当前低成本目标。其交互设计可参考，但不建议本轮迁移。
