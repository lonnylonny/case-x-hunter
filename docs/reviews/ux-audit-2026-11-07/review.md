# Case-X-Hunter 前端 UX 审查

审查日期：2026-11-07。方法：ui-ux-pro-max Skill、当前仓库代码阅读、Playwright MCP 实际操作及截图。定位依据：用户本轮说明，面向半导体封装质量工程师，优先完成相似案例查找、历史原因理解和证据核对。

## 结论与边界

建议保留原生 HTML/CSS/JavaScript，以 Tabler 改造页面与组件，先调整内容顺序、案例摘要和证据定位，再处理管理表单。当前瓶颈是信息架构与任务衔接，单纯换皮不能解决。

本次没有修改 `src/`、后端业务逻辑、数据集或依赖配置，没有 commit/push。新增内容仅为本审查目录的报告、截图和独立审查启动脚本；Playwright MCP 另生成根目录 `.playwright-mcp/` 操作快照。原有 `docs/reviews/ux-2026-11-07/` 未改动。

**实测环境必须区分：**

- 真实应用：`.venv/bin/uvicorn casetrace.api:app --host 127.0.0.1 --port 8027`。静态页面可用，`/dataset`、`/runtime-settings` 返回 503。无法从本次证据确定是配置、连接还是初始化问题，未修复数据库。真实成功检索、真实模型生成和持久化写入均未验收。
- 正常状态审查：本目录 `serve_audit.py`，8028 端口。复用真实页面、API、文件中的九案 dev-v3 合成快照和默认设置；只在独立进程替换数据库读取接缝。搜索实际调用既有检索代码，生成使用 `results/m4/dev-v3-answer-v10/q005.json` 固定回放。模型配置显示也是夹具状态，不证明真实模型可用。
- 网络失败、空库、零采用：通过 Playwright 临时响应拦截构造，仅验证展示。没有真实删除、上传、恢复或保存；未读取 locked-test 标签。回放截图最终使用 Q005 原文，不能据此评价模型回答质量。
- 桌面 1440×900、窄屏 375×812，补查 720×450。检查了页面级溢出；未执行完整屏幕阅读器、所有浏览器、200% 浏览器缩放或 WCAG 合规认证。
- 经用户授权，在 `/opt/google/chrome/chrome` 创建了指向 `/usr/bin/chromium` 的符号链接，以满足 Playwright MCP 的固定路径。没有保存 sudo 密码。

需要保留的优点：

- 搜索无需模型密钥，生成单独触发，费用和历史参考边界有提示。
- 空查询会阻止提交并聚焦输入框；异步检索禁用重复提交，结束后恢复；网络失败保留输入。
- 无命中、空库、零采用、系统错误分别表达。零采用没有误报系统故障。
- 资料库详情通过页面内返回能保留已应用筛选；编辑有固定操作栏、字段错误定位和离开保护代码。
- 来源结案声明与资料审阅状态分开；证据属于 Case，不强行绑定某条明细。对应 `renderDetail` 和行为文档。
- 颜色有集中变量、控件有标签与焦点样式，状态使用 live region。375px 首页、资料库、设置及展开回答均未发现页面级横向溢出。

## 推荐页面结构与交互

保留三个主入口，不新增统计首页。

```text
搜索历史案例 /
  当前资料范围（紧凑摘要）
  异常描述 + 示例 + 搜索
  结果条数 / 本次候选范围 / 处理反馈
  候选列表 → 单案历史结论 → 证据与来源
  基于当前描述生成调查参考（独立触发）
  当前信息缺口 / 采用与未采用说明
  折叠：检索参数、排名分数、运行记录下载

案例资料库 /library
  子入口：案例浏览（默认） | 资料管理
  案例浏览：关键词 + 常用筛选 → 已应用条件 → 列表 → 详情
  详情：概览 | 调查证据 | 批次明细 | 来源与修订
  编辑/新增：分区表单 + 固定保存与取消
  资料管理：概览、模板与规范、上传替换、恢复演示、主数据

设置 /settings
  模型状态与配置帮助
  回答输出上限
  高级检索：Top K（明确共享实例范围）
```

推荐主流程：

1. 首次用户输入异常现象、位置、发现阶段与已有检查事实，或直接使用现有合成示例；不用先理解快照、tokens 和 R3。
2. 点击搜索，按钮与状态立即反馈；完成后展示数量和候选摘要，提供“查看结果”定位。Top K 仅决定返回候选上限，不表示全库匹配总数。
3. 扫描候选异常差异和历史原因，再打开单案证据。已有字段可展示，缺失项显示“未提供”，不由前端推断相似理由。
4. 需要综合参考时单独生成。保留现有可直接生成能力，但将其视觉上置于搜索后的次级动作；文案说明仍会按当前描述检索，不能暗示只对勾选案例生成，现有 API 没有该能力。
5. 阅读生成理由、当前信息缺口及历史措施；点击来源定位具体证据。历史结论与当前判断持续分开，不显示“当前根因已确认”。
6. 进入资料库完整详情时使用可恢复链接。生成结果中的来源仍对应本次运行快照；如果资料库已更新，要显示版本差异，不能拿新记录替换旧回答证据。

比较方案采用两步：先统一候选行字段、详情区保持列表上下文；确有需求再增加 2–3 案并排比较。比较现有字段即可，缺失显示“未提供”，逐条保留产品与批次关联。资料库列表 API 不返回根因等全部字段，若按需读取 `/case`，需沿用同一 snapshot_id，不做逐行全量详情预取。

视觉建议：桌面列表可扩到约 1200–1280px，详情长文保持较窄阅读宽度；正文 14–16px、辅助说明不低于现有可读性水平，统一 4/8px 间距；一条清楚的边界提示、一个主动作；中性背景、轻边框、低层级卡片，不给每个字段嵌套卡片。375px 时筛选折叠、列表转摘要卡，关键状态保持可见。以上是设计建议，尚未实现或通过用户验证。

## 成熟工具参照与组件选择

本审查参照企业设计系统的具体模式，不假定 Case-X-Hunter 用户需要整套后台模板。Carbon 数据表强调表格工具栏、搜索/筛选、分页、展开内容等能力，可借鉴其“先扫描、再展开”的组织方式。[Carbon 官方数据表用法](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/components/data-table/usage.mdx?plain=1)

| 方案 | 适配现有栈 | 成本判断 | 决策 |
|---|---|---|---|
| Tabler Core | Bootstrap 5；支持普通 HTML，通过 CSS/JS 引入，无需迁移应用框架 | 可逐页替换样式、表格、导航、提示和表单；仍需自行完成状态管理、证据锚点与 History API | 推荐 |
| shadcn/ui | 官方 Vite 路线采用 React 和 Tailwind 等配置 | 对当前无构建链的三页原生应用，会增加框架迁移与重写成本 | 本轮不选 |
| 继续手写全部组件 | 与当前栈完全兼容 | 初期依赖最少，但一致性与复杂交互持续维护仍需投入 | 只保留必要领域渲染与交互 |

技术判断依据：[Tabler 简介](https://docs.tabler.io/ui/getting-started)、[普通 HTML 安装](https://docs.tabler.io/ui/getting-started/installation)、[shadcn/ui 官方 Vite 安装](https://ui.shadcn.com/docs/installation/vite)。结合 `pyproject.toml` 和 `web/` 的当前结构，Tabler 是本项目成本较低的选择，这是适配推断，不是实测迁移工时。

使用 Tabler 的方式：固定版本、本地托管静态 CSS/必要 JS、保留许可证；按需使用 header/nav、table、badge、alert、empty state、pagination、form 等组件。优先原生 details 和简单链接，不因换库加入动画、图表或复杂面板。现有全局 `.card`、`.actions`、button/input 规则需逐步收敛为页面作用域，避免与 Bootstrap/Tabler 类名冲突。组件库不自动提供业务排序、检索解释、证据真实性或完整可访问性。

## 分阶段改造计划及验收草案

以下为下一阶段讨论用验收草案，尚未获得实施授权。改造前应先确认验收标准，再开始实质功能工作。

| 阶段 | 内容 | 影响文件与接口 | 验收重点 |
|---|---|---|---|
