**交付行为：** 无需调查 Query 或模型密钥即可从网页了解当前数据集，筛选案例并查看完整明细、证据、来源和分组。

**Status：** 代码已实现，软件/浏览器回归通过；真实 PostgreSQL 验收已随 06 完成

### 1. 实现范围与代码接缝

本包交付“进入资料库 → 看概览 → 筛选分页 → 完整详情 → 返回列表”，并迁入已有资料管理控件。新增、编辑、删除、修订记录生成、统一写入冲突机制分别留给 03–05，不放置尚不可用的操作按钮。

| 当前仓库事实 | 02 的处理 | 依据 |

| API 只有当前资料概览、主数据、CSV 和恢复接口，没有案例浏览接口 | 新增列表和整案只读接口，不借用调查搜索作为浏览器 | [api.py](../../../../src/casetrace/api.py) |
| `load_snapshot` 在共享锁内读多表并核对完整摘要，返回 `LoadedSnapshot` | 每个浏览请求只读取一次快照，从同一对象构造身份、计数和内容；不另建缓存或检索索引 | [snapshot.py](../../../../src/casetrace/storage/snapshot.py) |
| 每个 Case 可有多个 Detail、多个 Case 级 Evidence，客户由产品推导 | 以 case_id 聚合子记录；筛选按单条明细判断，详情保留对应关系 | [dataset_model.py](../../../../src/casetrace/data/dataset_model.py)、[CONTEXT.md](../../../../CONTEXT.md) |

### 2. 固定公开读取契约

新增 HTML 入口 `GET /library`，使用 `web/library.html`、`library.js` 与既有 `app.css`。列表和详情为同页内部视图，无需引入路由库。以下为本包实现契约。

| 入口 | 参数 | 成功响应要点 |
|---|---|---|
| `GET /cases` | `keyword`、`product_id`、`customer_id`、`abnormal_process_id`、`detection_stage` 可选；`page=1`、`page_size=20`（1–100）；`snapshot_id` 首次可省略 | `dataset`、`total_count`、`matched_count`、`page`、`page_size`、`items`；`dataset.snapshot_id` 为本次全部内容的身份 |
| `GET /case?case_id=...` | 必填非空 `case_id` 及 `snapshot_id`，对应使用者当前列表 | `snapshot_id`、`case`、`details`、`evidences`、`groups`、`source`；记录完整且保留原顺序 |
| `GET /dataset/reference` | 增加可选 `snapshot_id`，保持既有无参数调用兼容 | 保留已有键，增加当前 `snapshot_id`、客户名称、产品族映射；产品同时给客户名称和产品族名称 |
| `GET /dataset` | 保留现有契约 | 在 `dataset_info` 增补来源类型供概览使用；已有调用方字段保持兼容 |

约束与状态：

- 复核时确认现有合法编号可包含 `/`、`.`、`..` 等文本，原拟定的路径参数会被路由或浏览器规范化。因此详情采用单一 query 入口传递编号，不收紧既有编号规则；已追加 HTTP 与真实浏览器回归。

- `snapshot_id` 一旦提供必须非空。列表翻页、筛选、详情、主数据请求均提交已展示身份；服务端在这次读回后先比较身份，再投影内容。过期返回 409 `snapshot_conflict`，提示刷新核对，不自动将旧请求切换到新资料。
- 同一快照找不到案例返回 404 `case_not_found`；过期快照下同案已消失仍先返回 409，避免误导为当前列表里的记录突然不存在。
- 非法分页、非法枚举等参数错误沿用 422 字段错误；此处没有新日期筛选。格式合法但不存在的产品、客户或工序编号返回零匹配，前端选项来自当前只读主数据。空筛选值按未筛选处理。
- 数据库配置、连接、未初始化、内容摘要异常沿用 503 安全说明；未预期故障 500。不得把服务故障转成 `items: []` 或暴露连接串。
- API 输入边界限制关键词长度为 200、筛选编号及快照身份长度为 200，分页为整数；拒绝未声明查询参数。客户端不提交数据库路径、schema 或模型参数。
- 每个读取只使用一次 `LoadedSnapshot`；浏览路径不调用 `prepare_answer_run`、`build_documents`、模型工厂或实例模型设置。主数据来自当前快照，不重新读取仓库 Excel 覆盖运行资料。

概览沿用名称、三类计数、更新时间、完整可用日期/依据及审阅状态。新增 `source_type` 表示载入途径：`csv_upload` 为现有 CSV（用 `import_format`/`is_upload` 识别），`builtin_demo` 为首次内置及恢复（固定基线身份或 `baseline_snapshot_id`），其余用 `other` 并明确显示其他运行资料；不靠运行 ID 前缀猜测，不把 CSV 上传等同于真实来源。03 引入人工维护标记后须相应更新展示，不能只凭保留的基线字段继续称为未修改演示库。

### 3. 列表聚合与筛选规则

1. 以现有 Case 源顺序作为稳定顺序；先筛选完整案例集合，再按 Case 分页。`total_count` 为整库案数，`matched_count` 为分页前匹配案数，均不能用本页长度代替。
2. 关键词去首尾空白，按不区分大小写的连续子串匹配，不进行分词、评分或语义搜索。范围仅为 Case 编号、异常描述、历史根因，以及任一 Detail 的生产批/客户批；不暗中扩展为证据和候选全文检索。
3. 产品、客户、发现阶段先在**同一条 Detail** 中同时匹配，再判断该案是否入选；客户通过该明细产品的 `product_customers` 获取。异常工序独立检查 Case 的 `abnormal_processes`；关键词和所有指定条件之间为 AND。
4. 匹配后，列表汇总仍描述整案：全部产品及各自客户（按 ID 去重，显示名称与编号）、全部已确认异常工序、全部明细的最早/最晚发现日期、明细和证据总数。不能只展示被筛中的那条明细，造成与详情计数不一致。
5. 列表保留完整异常描述字段，视觉上可限制行数，详情展示全文。产品/客户配对呈现，不能把多产品和多客户排列成不真实的组合。
6. 改变或清空筛选回到第一页；进入详情再返回保留筛选、页码。请求页超出有效范围时返回空 `items` 及真实匹配数，页面提示页码越界并提供回到第一页，不将其显示成空库或零匹配。

必须有反例夹具：一个案例的 D1 为产品 A/阶段 OQC，D2 为产品 B/阶段 Customer，两产品同属客户 A；另一案例的产品 C 属于客户 B。筛选产品 A + Customer，或产品 A + 客户 B 均不应入选；产品 B + 客户 A + Customer 应入选。再用匹配明细之外的子记录核对整案摘要没有被裁减。实现时已核对 [CR-04 的现有测试](../../../../tests/data/test_references.py)：同案不能混用不同客户，因此修正规划时写出的跨客户同案夹具，不改变冻结规则。

### 4. 完整详情及主数据

- `case` 保留现有模型所有字段：编号、异常、历史结案原因、措施、其他调查说明、异常工序；额外读取 `source.closure_status` 作为来源结案声明，不从根因文字推导 confirmed/NDF。
- 每条 Detail 完整显示编号、产品名称/编号、客户名称/编号、产品族、路线、两类批号、投批/发现日期、发现阶段、异常类型名称/编号、影响数量与处置。批号直接按文本显示，保留前导零。
- 每项 Evidence 完整显示编号、调查类型、自定义名称、结果和相关标记，清楚标为 Case 级调查项；不按数组下标或数量强行配给某条 Detail。
- 所属分组带完整 group 字段、本案 `association_reason`、成员编号；不增加分组编辑器，也不把其他成员当成本案子记录。
- `source` 保留该案现有来源形状并据类型展示。CSV 对每条记录列报告编号、报告名称、具体位置、原文件名/行号；内置合成来源列合成说明、sheet、Failure Mode 编号、选用候选及已有生成/模拟修订说明。不生成不存在的页码、逐明细报告或网页修订历史。
- 合成候选只说明生成沿革，不是已验证真实调查证据；既有模拟修订说明也不冒充 03 的网页修订日志。`draft_pending_human_review` 单独展示为待人工审阅，不与来源结案声明混用。
- 将既有主数据展开表迁到资料库，补客户名称、产品族和工序名称/编号。客户名称所需值从已有 `customers.customer_name` 读取：文件读取与 `build_reference_data` 同步扩展 `ReferenceData`，相邻等价性测试核对；保持主数据表、摘要结构及 schema 版本不变。
- 详情中的产品和工序背景只补当前主数据已有事实；路线上的允许工序不代表本案已确认异常工序。主数据只读，不返回模型密钥、连接信息、无关 qrels 或整个数据文件路径。

### 5. 页面状态、身份与入口迁移

- 三页共同导航为“搜索历史案例 / 案例资料库 / 设置”，当前页使用 `aria-current`。搜索页仍用当前数据集状态，保留旧回答/下载的旧身份处理。
- 资料库顶部为概览及默认折叠的技术身份区（运行快照、基线身份、原文件摘要、当前内容摘要），中间为筛选/列表/详情，CSV、恢复和主数据在独立的资料管理区。恢复沿用明确确认及原接口，上传继续说明整体替换。
- 从 `settings.html/js` 迁走资料相关 HTML 和处理逻辑，设置页只保留模型与检索部分，可提供资料库链接。保留 `/dataset`、下载、主数据和恢复接口 URL，不复制两份可写控件，不破坏现有模型设置回归。
- 首次列表获取 `dataset` 与身份；主数据随后用该身份读取，身份一致才启用筛选。已有列表后任何筛选/翻页请求都携带同一身份。详情使用对应列表身份；不得重新 GET 最新身份后悄悄拼进旧列表。
- 所有异步读取维护请求序号；筛选、翻页、切换详情、刷新以及资料替换会让旧请求失效。成功和失败的旧响应都不能覆盖当前页面。`pageshow` 恢复缓存页面时重新核对资料身份，并处理读取期间不可用状态。
- 409 明确显示“资料已变化，请刷新核对”，停用依赖旧身份的详情/筛选操作；不自动重试写入。用户主动刷新后重新载入一致视图，可保留筛选条件但重回第一页，旧详情不继续显示成当前资料。
- 上传或恢复成功后采用响应的新身份，清除旧详情、旧列表和主数据缓存，再以该身份读取；若随后再次变化则进入冲突态。写入进行中禁止同页重复上传/恢复和有干扰的刷新；网络结果不明时沿用 01 的核对提示，不自动重发。
- 分别呈现初次加载、请求失败（带重试）、零案快照、筛选无结果和页码越界。零案时本包提供已可用的导入/恢复入口；“新增”留待 04，05/06 再验收空库新建闭环。不得用坏链接提前占位。
- 动态文本使用 `textContent`/DOM 节点，来源与结果长文本保持换行；桌面一案一行，窄屏可用带标签的分行布局或局部横向滚动，控件不能被整页溢出挤出视口。不引入前端构建链。

### 6. 执行顺序与验证矩阵

先实现并验证“最小无筛选列表 → 完整详情”，随后加入筛选分页/快照拒绝，再完成入口迁移、浏览器交互与文档。每步沿用公开 HTTP 验证，不先建设所有后端或通用表单基础设施。

| 场景 | 入口与通过条件 |
|---|---|
| 无密钥基本浏览 | `tests/api/test_case_browser_api.py`：概览、列表、详情、主数据均成功；模型工厂、检索和模型设置读取被禁止调用 |
| 筛选分页 | 公开 HTTP 验证五个关键词字段、大小写/前导零、单项及组合筛选、同明细反例、稳定顺序、页边界；总数、匹配数、本页数各自正确 |
| 完整详情 | 九案及 CSV 多子记录夹具：完整字段、父子关系、来源记录位置、组理由正确；合成候选与真实报告字段不混淆，confirmed/NDF 与 draft 分开展示 |
| HTTP 错误与空态 | 无效参数 422、同身份无案例 404、旧身份优先 409、真实服务错误 503；零案、无匹配、越界分页分别验证，零案不构建空索引 |
