# 05：删除与空库

**交付行为：** 使用者明确确认后删除合法案例；破坏约束的删除被 validator 拦住；合法删至空库时界面及 API 有清楚行为，无回收站。

**Blocked by：** [03 编辑与修订记录](03-case-editing.md)。

**Status：** 2026-11-06 已实现；API、真实 PostgreSQL 与 HTTP 夹具浏览器通过；真实实例浏览器闭环待 06。

规范：[完整规格](../spec.md)。定位与执行次序见 [计划](../plan.md)。

## 验收标准

- [x] 删除前展示案例编号、摘要、明细/证据数和受影响组，说明无回收站；取消不改变任何数据。
- [x] 对删除后的完整候选集执行现有 validator；不足两案的组、悬空关系或其他无效结果均明确报错，不写入。
- [x] 不自动解散组，不允许单案组，不修改其他案例来绕过检查；直接 API 请求也不能绕过。
- [x] 合法删除移除该案、子记录、来源映射、入组关系和逐案修订记录，并同步顺序及快照摘要；其他案例和主数据不变。
- [x] 删除返回成功后，新列表、计数和新搜索不再包含该案；进行中的旧回答与下载记录保持原快照。
- [x] 删除检查预期快照身份；过期请求、重复提交及数据库中途失败不导致额外删除或不一致，错误可理解。
- [x] 能删除最后一个合法无分组案例，保留零案快照和主数据；不为删空而解散已有组。
- [x] 空库界面与筛选无结果区分，展示新增、导入及恢复演示的可用入口；尚未落地的跨包入口不得成为坏链接。
- [x] 对空库直接调用搜索/回答得到明确状态，不构建空索引、不调用模型、不发生意外 500。
- [x] 刷新和正常重启保留空库，不自动恢复默认九案；CSV 输入仍按既有至少一案规则校验。
- [x] 删除失败或取消不产生修订记录，不残留已删案例的隐藏备份。

真实数据库覆盖合法删除、多子记录级联、两成员组删一案被拦、三成员组合法删一案、写入失败回滚、旧版本冲突和最后一案。通过公开接口验证空库状态；浏览器核对影响确认与错误提示。

## 细化执行计划（2026-11-06，待确认）

执行总入口：[剩余工作计划](../remaining-work.md)。删除功能的授权不代表可以删除日常实例的用户资料；自动化验收仅使用隔离合成数据。

### 1. 删除接口与确认

- 增加 `DELETE /case?case_id=...`，JSON 必填 `expected_snapshot_id` 与严格布尔 `confirmed=true`。沿用 query 参数，保留特殊合法编号兼容。
- 确认面板从同快照完整详情展示编号、摘要、Detail/Evidence 数及所属组；可由已读取成员计算删除后的成员数，不另建预览服务。明确无回收站，取消只关闭面板。
- 服务端不信任前端数量或合法性判断；锁内重新读取、先核对身份，再检查案是否存在、生成候选并完整校验。成功 HTTP 200、`status=deleted`、`case_id` 和新 `dataset`；409 冲突，404 当前身份无此案，422 未确认或违反规则，503 存储故障。重复旧请求优先报冲突，不重复变更。

### 2. 候选与持久性

移除目标案及其 Detail/Evidence、Membership、来源、修订记录。保留所有 Group 实体，交给 validator 判断结果；三成员组删至两成员可合法成功，两成员组删一案必须回滚。不自动删组、改组或修改其他案例来换取通过。

复用现有锁与原子替换，维护当前顺序、摘要及新快照身份；沿用日期/依据、主数据与设置。失败不产生修订；成功不保留被删除案的隐藏全文或日志副本。旧回答的已有运行记录按原规格保留，不将其变成当前资料的备份/回收入口。

最后一个合法无分组案删除后保留零案快照，`sources` 和逐案修订清空。已有 `prepare_snapshot` 按“是否存在有效快照”保留资料，补测试证明实体数为零不能触发默认导入。CSV 输入仍至少一案，不放宽导入约束来制造空库。

### 3. 空库 API 与页面

有效且时点匹配的 `/search`、`/answer` 在读取到零案快照后、进入检索/模型路径前，返回 HTTP 200、`status=empty_dataset`、中文说明、`record=null`。前端将其作为业务状态呈现，并链接资料库；无运行记录则不生成下载。输入与时点校验仍适用；服务未初始化/不可用仍为原错误，非空库零命中仍为 `no_hits`。

在资料库明确区分“总数为零”和“筛选无结果”，空库提供新增、CSV、恢复九案三个入口。删除成功刷新概览/列表，关闭已删案详情并处理最后一页回退；冲突要求重新读取并再次确认。网络结果不明不自动重删，保留影响信息供核对。提交期间控制重复操作，迟到详情不能恢复已删案。

## 实施记录

实际改动：

- `data/case_editing.py`：新增 `prepare_case_deletion`，移除目标案、子记录、成员关系、来源映射与该案修订（修订为空时删除 `case_revisions` 键），保留全部 Group 交给完整候选校验；违反 CR-38 等规则返回可定位错误。
- `storage/snapshot.py`：新增 `delete_case_snapshot`，锁内先核对 `expected_snapshot_id` 再检查案例存在性，以 `delete-<uuid>` 身份原子替换并读回。
- `api.py`：新增 `DELETE /case?case_id=...`（JSON 必填 `expected_snapshot_id` 与严格 `confirmed=true`）；200 deleted／409／404／422 errors／503。`/search`、`/answer` 在读取零案快照且时点校验通过后、进入检索或模型前返回 200 `status=empty_dataset`、`record=null`；非空库零命中仍为 `no_hits`。
- 页面：详情新增“删除案例”，确认面板展示编号、摘要、明细/证据数、所属组及删除后剩余成员数，并明确无回收站；成功刷新列表与身份，409 要求刷新核对，422 展示拦截原因，结果不明不自动重删。空库提示同时指向“新增案例”、CSV 导入与演示恢复；搜索页把 `empty_dataset` 作为业务状态呈现并链接资料库。
