## 拟确认的具体行为

1. **新增**：资料库显眼入口复用已有中文分区表单及顶部固定保存栏；Case/Detail/Evidence ID 全部由服务端生成，默认不入组。Case 及每个子记录必须有首次来源；批号前导零保留；完整可用日期默认沿用，可随保存明确调整。首次修订类型为 `create`，仍待人工审阅。
2. **删除**：详情页展示编号、摘要、子记录数量及受影响组后明确确认；删除时重新核对快照并校验完整候选。CR-38 不变，三成员组可合法删为两成员，两成员组删一案须拦住；不自动解散组。成功移除关联来源及该案修订，无回收站。
3. **空库**：保留零案快照及主数据、设置和日期；正常重启不回填。有效 `/search`、`/answer` 请求返回 HTTP 200、`status=empty_dataset`、`record=null` 和可理解的管理入口提示；不构建检索器、不调用模型。非空库检索无结果仍使用原 `no_hits` 行为。输入/时点校验继续有效。
4. **并发**：新增、编辑、删除、CSV、恢复统一检查 `expected_snapshot_id`；同一旧身份最多一个写请求成功。409 或结果不明时保留可保留的输入，明确刷新核对，不自动重发写操作。
5. **交付**：验收中增删改、CSV 替换和演示恢复只发生在隔离合成数据实例；日常实例只更新 API 并读回核对，不用用户真实资料做破坏性测试。

## 环境、授权与边界

确认本计划即授权上述功能实施、必要回归修复、仓库文档/截图、隔离测试实例的合成数据写入与本次自建测试 schema/容器/卷的定向清理，以及构建并仅更新现有 API 服务。更新 API 会有短暂不可用；不重启数据库、不重跑初始化覆盖资料。

先使用 `CASETRACE_TEST_DATABASE_URL` 的独占测试 schema；已有夹具见 [tests/storage/conftest.py](../../../tests/storage/conftest.py)。若缺少可用测试连接，在本仓库忽略的 `tmp/` 中准备独立 Compose 配置、随机测试凭据与临时端口，使用独立项目名和新建测试卷。只管理本次创建且可核对归属的资源，不调整现有卷或数据库账号。配置只在程序内部读取，输出仅报告配置存在性/连接结果，不显示密码或连接串。工具权限如需批准，按工具规则处理。

若 Docker/测试库无法使用且无法在授权范围解决，继续完成可独立的实现与验证，真实库验收保持未完成，不能将 skip 写成通过。只有出现必须更改冻结规则、迁移/删除实际用户资料、跨仓库访问等新增范围时，才提出具体方案另行确认。没有自动 commit/push、远程 issue 或付费模型调用。
