## 已确认实施方案

- 唯一 CSV 模板，record_type 为 case/detail/evidence；子记录通过 case_id 关联，Evidence 只属于 Case。分组不在本次上传格式中。
- 复用现有 CR 字段、关系、主数据及批号一致性检查。GR 采样约束及候选库来源检查仅用于原合成资料，不施加于用户上传；不扩展现有语义校验覆盖。
- 每条记录必填 source_document_id、source_document_name、source_location，不继承上一行、不用占位；保留上传文件名和 CSV 物理行号。来源真实性及语义由人工审阅。
- 实施审查补齐：Case 行沿用来源元数据 closure_status，必填 confirmed/NDF，以便与合成入口共用既有 CR-35 的 related Evidence 门槛；不新增冻结实体字段，不从根因文本猜状态，不改变上传的 draft 审阅状态。
- 上传填写数据集名称、整份资料的可用日期与依据；声明该日期前全部案例已结案且内容完整。登记独立快照与 CSV/主数据摘要，不从 detection_time 推导结案时间。上传统一为 draft，不继承指标。
- UTF-8（可带 BOM）、ISO 日期、多值分号分隔；同类型主键文件内唯一，不存在的外键和无子记录 Case 拒绝。上限 5 MiB、500 Case、10000 条记录，空数据拒绝。
- 先完整校验，再单事务整体替换当前业务数据与元数据；失败回滚。主数据复用实例原有内容，不修改原始文件、评估集或结果。
- 已取得快照的检索/回答不中断，沿该快照完成。每次读回取得一致数据；新请求与上传交错时的额外排队或拒绝策略不在本轮增加。
- 设置页提供下载、说明、上传、当前状态与错误反馈；搜索页读取当前登记日期。模型参数留给 04。

## 执行顺序与验收接缝

1. API 下载与复杂案例完整导入：一个 Case、两个 Detail、三个 Evidence；逐条来源可定位。
2. 失败反馈与事务：缺列、空必填、非法主数据、重复 ID、日期错误、写入失败均保留旧数据。
3. 读取与持久性：替换后检索/回放回答使用新身份，进行中的旧回答完成，重新连接及启动准备保留上传数据。
4. 浏览器下载→上传→查询、失败提示，保存截图；运行完整软件回归并记录真实验证和限制。

测试接缝沿已确认的 API 和真实 PostgreSQL，模型采用离线回放；不调用付费模型，不自动提交。
