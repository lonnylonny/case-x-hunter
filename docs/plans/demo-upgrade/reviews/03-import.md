# 03 固定 CSV 更新资料：实施与验证记录

日期：2026-10-23。03 已完成：代码、自动验证、双向审查和用户浏览器四步验收均通过；用户回报「测试没问题」。本次未收集页面截图。未自动提交、发布、改写原始数据或调用付费模型。

## 交付

- `/settings` 提供固定模板、完整合成示例、主数据与填写说明、当前状态和上传反馈。搜索页通过 `/dataset` 使用当前资料的名称、数量、更新时间与登记日期。
- 唯一 CSV 的 `record_type` 区分 Case、Detail、Evidence。完整示例为 1 Case、2 Detail、3 Evidence，后两类只通过 `case_id` 关联，不建立错误的 Detail—Evidence 配对。分组不在上传格式中。
- 每行必填来源报告编号、名称、具体位置，保存文件名与物理起始行号。上传文件 SHA-256 在解码前计算，内容摘要覆盖全部实体、主数据、来源、顺序及登记元数据。
- CR 复用现有入口；合成的 GR 采样与候选库检查不套用到上传。审查发现 CR-35 的已有机械门槛需要保留，因此 Case 行沿用来源元数据 `closure_status=confirmed/NDF`，与合成入口共用 `check_confirmed_evidence`；不新增冻结实体字段，不从自由文本猜状态。
- 上传固定 draft，保存独立 `upload-*` 身份、可用日期与声明依据。发现时间不能证明结案时间，声明真实性和证据语义仍需人工审阅；不继承原评估指标、Query 或标签。
- 替换前完整校验；在事务内按逆依赖删除旧业务记录，写入全部新内容和元数据。主数据保持原实例内容，任何写入失败回滚。读回共享锁覆盖多表读取，写入和启动准备锁定同一元数据表；生成期间没有数据库连接或锁。
- 正在生成的旧回答继续按原快照完成。新请求与上传交错时不增加额外产品排队策略，仍保证单次读取完整一致。

详细格式：[upload-format.md](../../../data/upload-format.md)。

## 实际自动验证

完整回归：**832 passed、12 skipped、169 subtests passed**，耗时 23.75 秒。12 项跳过为本机缺少 PowerShell 的既有启动用例；PostgreSQL 上传测试实际执行，没有用 skip 代替验收。

实际通过临时入口执行 `uv run --locked --no-sync python /tmp/casetrace-upload-tests.py -q`。临时入口从本机未提交配置构造仅供测试进程的 `CASETRACE_TEST_DATABASE_URL`，恢复其余原始环境后调用 pytest，未输出凭据、未修改 `.env`。标准复跑方式为先按 PostgreSQL 文档配置测试 URL，再执行 `uv run --locked --no-sync pytest -q`。

验证包括：

- 无数据库下载模板与完整示例，页面和静态资源托管；上传元数据、额外参数和 5 MiB 请求流上限。
- 真实 PostgreSQL 成功替换内置九案为一个复杂案例，搜索只返回新 Case，完整取回两个 Detail、三个 Evidence、六条来源；上传之间再次整体替换也不混入旧数据。
- 缺列、错误编码、空文件、非法 CSV、空必填、非法产品/异常/工序、悬空父记录、重复 ID、日期错误、Other 缺名称、数量格式/数据库整数溢出、空结案声明等失败保留旧数据。
- confirmed 缺 related 被 CR-35 拒绝并定位 Case 行；NDF 允许全部调查项 uncertain。上传允许超过合成 GR 的 5000 颗限制，保持 PostgreSQL integer 存储范围。
- 数据库触发器在 Evidence 写入阶段主动拒绝，确认此前删除和写入的业务记录及元数据均回滚，旧数据仍可搜索。
- 启动 `prepare` 保留上传数据，重建应用与两次实际启动/停止独立 Uvicorn 进程后，状态及搜索结果一致。原样例与主数据文件摘要保持相同。
- 离线回答回放通过引用定位，模型收到上传来源；阻塞模型回放期间完成上传，旧回答仍成功返回旧快照，后续搜索使用新数据。
- 带换行单元格的 CSV 使用正确物理行号；ID 包含 `]` 时错误也能定位。

另外通过 Python 编译、两个 JS 文件语法检查与 `git diff --check`。没有配置独立类型检查器，未宣称通过额外静态类型检查。软件测试与回放不证明真实模型回答质量。
